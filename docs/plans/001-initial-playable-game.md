# План: первая играбельная версия The True Path

## Пожелание

Создать на Defold 2D-игру, в которой игрок управляет главным героем, проходит лабиринт и достигает выхода. Собрать игру для HTML5 и опубликовать рабочую версию через GitHub Pages.

## Текущее состояние

- Репозиторий очищен от прежнего Godot-шаблона коммитом `5f884ba`.
- Проекта Defold и игровых ресурсов пока нет.
- В репозитории действуют обязательные фазы: план, дизайн, реализация и проверка с отдельным утверждением плана и дизайна.
- Добавлены локальные skills для Defold-разработки, проверки игрового поведения и выпуска HTML5 на GitHub Pages.

## Результат и границы

В результат первой версии войдут:

- запускаемый проект Defold с одной законченной игровой сессией;
- один лабиринт с однозначной стартовой позицией героя и доступным выходом;
- управление героем, запрет прохода сквозь стены и определение достижения выхода;
- понятная обратная связь о цели, управлении и победе;
- возможность начать игру заново без перезагрузки страницы;
- корректная HTML5-сборка и автоматическая публикация на GitHub Pages;
- проверки правил лабиринта, основного игрового пути и браузерной сборки.

За рамками первой версии остаются несколько уровней, редактор уровней, процедурная генерация, сохранения, таблица результатов, сюжетная система и сложная прогрессия. Их можно будет добавить отдельными пожеланиями после появления устойчивой основы.

## Предположения и решения

- Первая версия будет компактным MVP с одним вручную заданным лабиринтом.
- Игра должна быть полностью проходима с клавиатуры в настольном браузере.
- Графика и звук первой версии должны образовывать цельный минимальный стиль без зависимости от платных ассетов.
- Конкретная модель движения, размеры игрового поля, камера, визуальный стиль, набор дополнительных устройств ввода и формат хранения лабиринта будут определены в дизайн-документе.
- Для воспроизводимой сборки будет закреплена конкретная версия Defold/Bob.
- Публикация будет выполняться GitHub Actions через официальный механизм Pages artifact deployment.

## Затрагиваемые области

- `game.project` — настройки приложения, bootstrap, физики, отображения и HTML5.
- `main/` и игровые каталоги, уточняемые дизайном, — коллекции, объекты, скрипты и данные уровня.
- `assets/` — собственные или разрешённые графические и звуковые ресурсы.
- `input/` — привязки утверждённых способов управления.
- `test/` — проверки Lua-правил и engine-зависимых сценариев.
- `scripts/` или `tools/` — воспроизводимые локальные команды сборки, если они потребуются.
- `.github/workflows/` — проверка HTML5 bundle и публикация GitHub Pages.
- `docs/design/001-initial-playable-game.md` — утверждённое устройство игры, сценарии и журнал проверок.

## План проверки

- Проект собирается закреплённой версией Bob без ошибок и создаёт полный `wasm-web` bundle.
- Автоматические проверки подтверждают границы лабиринта, блокировку стен, допустимые перемещения, достижимость выхода, однократную победу и чистый перезапуск.
- В браузере игра загружается по HTTP без необработанных ошибок и отсутствующих ресурсов.
- Игрок может прочитать управление, пройти лабиринт, получить состояние победы и начать заново.
- Потеря и возврат фокуса не оставляют движение в зажатом состоянии.
- Утверждённые размеры окна сохраняют игровое поле и GUI пригодными для использования.
- GitHub Actions успешно публикует bundle, а тот же основной сценарий проходит по публичному Pages URL.

## Риски и открытые вопросы

- Поклеточное движение, тёмная пиксельная стилистика, клавиатурный ввод и логическое разрешение `640×360` реализованы по утверждённому дизайну.
- Сенсорное управление остаётся отдельным будущим изменением.
- Настройки репозитория GitHub Pages могут потребовать однократного выбора источника **GitHub Actions**, если первый deploy job сообщит об отсутствии Pages environment.
- Слуховую оценку двух эффектов нужно выполнить вручную в обычном браузере; автоматические проверки подтверждают загрузку и вызов валидных WAV без ошибок.
